# 蝶威量化因子挖掘大赛 - 参赛指南

## 一、比赛是什么？（通俗解释）

简单来说，这是一个**量化投资比赛**。你的任务是：

> **用A股的高频行情数据（每几秒一条的快照数据），算出一个"打分公式"（因子），给沪深300成分股每隔15分钟打一次分。系统会用你的打分来选股和交易，看看你的打分能不能赚到超过大盘（沪深300指数）的钱。**

具体流程：
1. 平台给你2023-2024年的A股高频快照数据（价格、成交量、买卖挂单等）
2. 你写一个Python函数 `main(datasource, start_date, end_date)`
3. 这个函数要返回一个表格，包含三列：`date`（时间）、`instrument`（股票代码）、`factor`（因子值/打分）
4. 每个交易日有16个时间点（每隔15分钟），每个时间点给约300只股票打分
5. 系统会自动用你的分数选分最高的60只股票进行模拟交易
6. 根据模拟交易的收益和夏普比率来给你排名

**核心目标**：因子值越大的股票，未来15分钟涨得越多 → 你的排名越高 → 奖金越多（总奖金池12万元）。

## 二、官方Demo逻辑

官方Demo（`demo/demo.ipynb`）使用的是**加权订单簿压力因子（Order Book Pressure）**：

1. **计算5档加权买卖量**：对盘口1~5档的挂单量用指数衰减加权（离盘口越近权重越大）
2. **计算不平衡度**：`(买方加权量 - 卖方加权量) / (买方加权量 + 卖方加权量)`
3. **除以价差**：不平衡度 / √(相对价差)，得到"原始压力"
4. **15分钟窗口内标准化**：Z-Score标准化
5. **波动率调整**：高波动时打7折
6. **tanh缩放**：限制到(-1, 1)区间
7. **方向取反**：最终因子 = -1 × factor

**逻辑**：买盘挂单远大于卖盘时（且价差小），说明买方力量强，但Demo取反做反转。

## 三、各策略分析

### 1. 动量反转（动量反转.ipynb / momentum_py-v3.ipynb）
- **策略**：计算15分钟窗口内收盘价vs均价的偏离度，取反转方向
- **公式**：`factor = -tanh((close - avg) / avg × 10)`
- **优点**：逻辑简单清晰，日内均值回归是经典微观结构特征
- **缺点**：单一信号，没有利用盘口信息，在趋势行情中表现差

### 2. 价格排序（价格排序.ipynb）
- **策略**：每15分钟截面内按收盘中间价排序，低价股得分高
- **公式**：`factor = 归一化排名 ∈ [0, 1]`（低价=1，高价=0）
- **优点**：截面因子，天然抗市场beta
- **缺点**：低价效应被BARRA中性化后可能被消掉大部分，逻辑较弱

### 3. 价格&反转复合（价格&反转复合.ipynb）
- **策略**：0.2 × 价格排序 + 0.8 × 动量反转
- **优点**：复合因子比单因子更稳健，降低了单一信号失效风险
- **缺点**：权重固定（0.2/0.8），没有自适应调整

### 4. 订单簿压力（订单薄压力.ipynb）
- **策略**：与Demo几乎相同的订单簿压力因子，但方向为正（factor × 1）
- **优点**：利用了盘口微观结构信息
- **缺点**：与Demo重复度高，SQL计算较慢

### 5. 量价相关性（量价相关性.ipynb）
- **策略**：计算15分钟窗口内价格收益率与成交量变化的皮尔逊相关系数
- **公式**：`factor = Corr(returns, volume_delta)`
- **优点**：捕捉量价背离/配合关系，角度独特
- **缺点**：相关系数在样本少时不稳定，信噪比低

## 五、最优方案概述

我在 `mycode/my.ipynb` 中提供了一个**多因子复合方案**，融合了以下信号：

1. **订单簿不平衡因子**（Order Book Imbalance）：10档加权买卖量差异
2. **日内动量反转因子**（Intraday Reversal）：收盘价vs均价偏离
3. **成交量加速度因子**（Volume Acceleration）：成交量变化趋势
4. **大单净流入因子**（Net Order Flow）：利用盘口深度估算资金方向

最终复合公式：
```
factor = tanh(w1 × OBI_zscore + w2 × Reversal + w3 × VolAccel + w4 × NetFlow)
```

这个方案的优势：
- 多信号融合，降低单因子失效风险
- 同时利用了盘口微观结构和价量信息
- tanh缩放 + Z-Score标准化，减少极端值影响
- 纯SQL实现，计算效率高，内存占用低
